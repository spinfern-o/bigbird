PHOTOFORGE ROADMAP - WORK SPLIT INTO TWO PARALLEL TRACKS
========================================================

The remaining work is split into two tracks that can be built at the same time.
Each track mostly owns its own files, so the two developers rarely edit the same
code. Where they must touch shared files, follow the "Shared files" rules below.

  TRACK A - Selections & AI
  TRACK B - Pro Editing & Lightroom Features

Workflow for everyone:
  * One branch + one pull request per numbered task (e.g. branch "a2-ai-framework").
  * Keep PRs small. Rebase on main before opening a PR, and after the other
    track merges something.
  * Every new control gets a plain-English tooltip and a status-bar hint.
    PhotoForge is for beginners.
  * Every change must be undoable (use doc.push_undo before changing state).

--------------------------------------------------------------------------------
SHARED FILES - RULES TO AVOID CONFLICTS
--------------------------------------------------------------------------------
These files are used by both tracks. Keep edits to them small and additive
(add new methods/menu entries; don't reorganise existing code in the same PR):

  app/document.py     A adds `selection`; B adds `Layer.mask`. Coordinate on
                      compositing: B owns composite(); A only reads the selection.
  app/canvas.py       Each new tool goes in its own clearly named methods.
                      Tool ids: A uses "select_rect", "select_ellipse", "lasso",
                      "ai_select"; B uses "clone", "heal", "gradient", "radial".
  app/main_window.py  Add menus/actions through small helper methods
                      (e.g. _build_ai_menu, _build_retouch_tools) rather than
                      editing existing blocks.
  app/icons.py        Append new icon functions only.
  requirements.txt    Append only. (A adds onnxruntime-directml, requests.)
